# 2025年电赛 E题：简易自行瞄准装置 (K230 视觉程序设计方案)

## 一、 系统架构与前提设定

### 1. 硬件平台与开发环境
*   **核心主控**：嘉楠 K230 (负责视觉识别与坐标解算)
*   **开发框架**：CanMV (基于 MicroPython，开发效率高，内置机器视觉库)
*   **下位机**：TI MSPM0 系列 (负责云台舵机控制、小车运动控制)
*   **通信接口**：UART (K230 串口发送目标坐标偏差至 MSPM0)

### 2. 相机安装方案：眼在手上 (Eye-in-Hand)
*   **安装位置**：摄像头与激光笔平行安装，共同搭载于二维云台上。
*   **控制逻辑**：将复杂的“三维空间几何解算”降维成“图像二维 PID 跟踪”。K230 识别到靶心在画面中的坐标 $(cx, cy)$ 后，计算与画面正中心 $(W/2, H/2)$ 的偏差量 $(dx, dy)$。下位机通过 PID 算法调节云台，使得偏差趋于 0，即可实现激光精确打击。这是实现高精度（误差 $\le 2\text{cm}$）的核心保障。

## 二、 核心视觉识别算法

系统主要采用**传统机器视觉算法 (基于 `image` 模块)** 保证高帧率和稳定性。

### 1. 靶心定位策略 A：基于黑色外框四角 (新方案)
当红色靶心较小或环境光干扰大时，识别 A4 纸边缘 1.8cm 宽的黑色胶带框是更稳定的选择。
*   **图像预处理**：
    *   `img.to_grayscale()`：转换为灰度图以提高处理速度。
    *   `img.binary([(0, 60)])`：二值化处理，提取低亮度的黑色边框。
*   **矩形/四边形提取**：
    *   使用 `img.find_rects(threshold=10000)` 直接寻找矩形。
    *   或者使用 `img.find_line_segments()` 寻找四条长直线并计算交点，得到四个顶点 $P_1, P_2, P_3, P_4$。
*   **四角排序逻辑**：
    *   计算四个点的 $(x+y)$：最小值是左上 (TL)，最大值是右下 (BR)。
    *   计算四个点的 $(x-y)$：最大值是右上 (TR)，最小值是左下 (BL)。
*   **中心坐标计算**：
    *   **算术平均法**：$Center_x = (TL_x + TR_x + BR_x + BL_x) / 4$，对于近距离视角足够精确。
    *   **对角线交点法**：计算直线 $(TL, BR)$ 与直线 $(TR, BL)$ 的交点，能更好处理透视畸变严重的情况。

### 2. 抗干扰处理：激光光斑识别过滤
在紫光感光纸上会残留蓝色光斑痕迹，需要避免误识别。
*   **策略**：通过降低摄像头曝光时间 (Exposure)，使环境变暗，只有当前高亮的激光点才会显现，历史残留痕迹将因亮度低而被过滤。
*   **注意**：在“眼在手上”方案中，因为激光与摄像头平行，激光在画面中的位置相对固定（只需标定一次）。通常情况下，只需识别靶心，不强制要求在画面中识别激光点。

## 三、 针对赛题要求的具体策略

### 1. 基础要求（静态与定点瞄准）
*   **逻辑**：
    1. K230 获取靶心坐标 $(cx, cy)$。
    2. 计算误差：$E_x = cx - \text{Center}_x$，$E_y = cy - \text{Center}_y$。
    3. 通过 UART 将 $(E_x, E_y)$ 发送给 MSPM0。
    4. MSPM0 执行云台增量式 PID 控制。
*   **关键点**：K230 端保证高帧率，下位机调好 PD 参数防止震荡，实现 2 秒/4 秒内的快速锁定。

### 2. 发挥部分 1&2（动态跟随瞄准）
*   **逻辑**：在小车沿轨迹运动时保持锁定。
*   **关键点**：单纯图像反馈存在滞后。K230 可通过计算连续两帧靶心的位移差 $(cx_t - cx_{t-1})$，预判靶心移动趋势，将此“速度”作为前馈量一同发送给 MSPM0，提升动态跟踪精度。

### 3. 发挥部分 3（靶面上同步画 6cm 圆弧）- 难点攻坚
由于摄像头存在透视畸变，直接在图像中画圆会导致靶面上呈现椭圆。
*   **解决方案：透视变换 (Perspective Transform)**
    1.  **标定靶面**：识别靶面外围黑色胶带构成的矩形，获取四个顶点坐标。
    2.  **建立映射**：以这四个顶点为基准，使用透视变换算法，将倾斜畸变的图像坐标系映射为一个正视的、标准比例的虚拟坐标系。
    3.  **计算目标点**：在标准坐标系中，以靶心为原点，根据时间或小车运行的圈数比例，计算出半径 6cm 圆弧上的当前目标期望点坐标。
    4.  **逆映射**：将该虚拟目标点逆透视变换回实际图像坐标系，作为云台 PID 追踪的“新靶心”。

## 四、 串口通信协议定义

为了确保数据传输的高效与准确，K230 与 MSPM0 之间建议采用定长数据帧格式：

*   **波特率**：115200 bps
*   **数据帧长度**：8 Bytes
*   **格式**：

| 字节 | 定义 | 说明 |
| :--- | :--- | :--- |
| Byte 0 | 帧头 | 固定的起始标志，如 `0x55` |
| Byte 1 | 状态字 | `0x00`: 未找到目标, `0x01`: 找到靶心, `0x02`: 画圆模式... |
| Byte 2 | X 误差高 8 位 | X 轴坐标偏差 (带符号) |
| Byte 3 | X 误差低 8 位 | X 轴坐标偏差 |
| Byte 4 | Y 误差高 8 位 | Y 轴坐标偏差 (带符号) |
| Byte 5 | Y 误差低 8 位 | Y 轴坐标偏差 |
| Byte 6 | 校验和 | Byte 1 至 Byte 5 的累加和 (低 8 位) |
| Byte 7 | 帧尾 | 固定的结束标志，如 `0xAA` |

## 五、 后续开发步骤建议

1.  **阶段一：验证红色靶心识别**。编写简单的 CanMV 脚本，调整阈值，在 IDE 缓冲区中能够稳定框出靶心。
2.  **阶段二：打通通信与闭环**。编写串口发送代码，与 MSPM0 联调，实现云台追踪静止靶心。
3.  **阶段三：动态追踪优化**。在小车运动时，调整下位机 PID 算法及帧率，解决画面拖影和控制滞后问题。
4.  **阶段四：攻坚“画圆”功能**。研究并实现透视变换算法模块。
